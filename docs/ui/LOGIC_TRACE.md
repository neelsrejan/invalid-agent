# Guided page logic trace

The page is one script. It walks Week 1, then Week 2, then Week 3, then Week 4. Each week has six parts: complaint, numbers, charts, what gets logged, root-cause notes, and a wrap-up. Next stays off until that part's key insight is confirmed, or the reader presses Show me and the page logs it. Start week N+1 is that same Next button on the wrap-up, so it stays off until the wrap-up insight is logged. Python computes every count. A language model may only rephrase the talk-back reply.

There is no week switcher and no free-explore panel. Those were the old way to skip ahead.

## main

`app/streamlit_app.py:824` `main` loads dotenv and Streamlit secrets, then `load_settings`. It sets `public` from `DATA_BACKEND=openfda`. The banner is `PUBLIC_BANNER` or `PRACTICE_BANNER` from `src/invalid_agent/ui/plain.py`. `app/streamlit_app.py:106` `_scenarios` lists the cases. On the hosted app that returns only `cases/openfda_ooi.yaml` and `cases/openfda_jje.yaml`. A local run appends those two after every `scenarios/*.yaml` file.

Before those imports, `ensure_checkout` (`src/invalid_agent/fresh.py:118`) drops `invalid_agent` modules whose files sit outside `src`, whose files are newer than the mtime `note_imports` (`src/invalid_agent/fresh.py:146`) recorded, or that have no stamp yet and are out of date with the file on disk. Out of date means the loaded module is missing a public name the file defines, or the bytecode it was loaded from records an older source time. Before the first `note_imports`, a missing or unreadable bytecode file also drops an unstamped module, which is what happens when Python is started with `-B` and the process still holds the previous release. After `note_imports`, a missing bytecode file does not, by itself, drop a module that already has every name in the file. A newer bytecode file written by another process does not keep a module that is missing a name. A process that still holds the previous release has no stamps, so that check is what lets the new code import `gloss_once` and `part_fact`. `main` calls `note_imports` again after the page runs, so a module imported during the page is stamped before the next rerun. A rename of a step in memory does not reload the package. `.streamlit/config.toml` sets `fileWatcherType = "poll"` so a deploy can drop a changed module. `none` left the previous module in memory, and the first load after a deploy could still raise `TypeError` until a reload.

`app/streamlit_app.py:824` calls `_init_state` and `_render_guided`. `main()` runs at import so `streamlit run` and AppTest both enter here.

## _init_state

`app/streamlit_app.py:115`. The first loop re-assigns each key in `_KEPT_KEYS` (`app/streamlit_app.py:54`) to itself when the key is already present.

Streamlit deletes a widget key at the end of a run that did not render that widget. `scenario_id` is the case select box, and it is drawn only on week 1, part 1. `stratum` is the break select box, drawn only on the charts part. `audience` is the note radio, drawn only on the notes part. `story_week`, `beat`, `unlocked_week`, and `open_items` are not widgets. Re-assigning them is harmless and keeps the same habit as the widget keys. The page does not keep a separate `week_insights` list. Week N insights are the open items for that week.

`talk_text` is drawn on every part, so it is not in `_KEPT_KEYS`. After a reply, `_apply_talk` bumps `talk_nonce` (`app/streamlit_app.py:240`). The box key includes that number, so the next run draws an empty box. The page does not pop `talk_text`.

After the re-assign, the function clamps `story_week` so it cannot be higher than `unlocked_week`, and `unlocked_week` cannot be higher than 4. A session value of week 4 on a fresh visit is put back to week 1. Changing `scenario_id` clears the story, the insights, the open tickets, and the deck, and locks the walk back to week 1.

The numbers part uses `direction_head`, which does not say "This chart". The charts part and the wrap-up still use `direction_sentence`, which includes that sentence once.

The logged part and the notes part also open cached write-ups from `_case_sections` (`app/streamlit_app.py:538`). That call runs `run_case(..., llm=DeterministicLLM())`. It does not set `LLM_BACKEND` in the environment, so another session can still use Groq. Those write-ups cover the whole file, not the date slice on screen. Each block says the rate in the sentences above the block is the one for this week. `sections_from_run` (`src/invalid_agent/ui/records.py`) turns the records into plain sentences and drops a sentence that still has unexplained jargon or a server path. Markdown marks are stripped before that check, so a word wrapped in underscores is still checked. An underscore inside an id stays. Each block is an expander, closed by default. The talk box uses a new key after every reply (`talk_nonce` in `_apply_talk`). That empties the box. Deleting the old key did not, because the browser sent the typed value back on the same run.

`_render_carried` (`app/streamlit_app.py:341`) lists typed tickets and flags from earlier weeks at the top of week 2, 3, and 4. A Show me insight stays on the week where it was logged. It does not print "Flag 1: Flag 1". `_render_talk` (`app/streamlit_app.py:370`) is on every part, including the finished screen. It does not insert a gloss into that echo. `_render_insights` (`app/streamlit_app.py:356`) prints `Week N insights` under the reply. A Show me line does not take the place of a later ticket. `_reveal` (`app/streamlit_app.py:663`) writes the Show me item and `_mark_done` (`app/streamlit_app.py:297`) records the part. `_nav` (`app/streamlit_app.py:699`) draws Back, Show me, and Next. Next is disabled until the part is done.

Show me logs that part's key sentence as an Insight and then enables Next. It does not take a Your ticket number. ## The week view

`build_week_view` (`src/invalid_agent/ui/story.py:59`) slices the frame with `slice_through_story_week` (`src/invalid_agent/ui/story.py:33`). Week 1 keeps the first quarter of the dates. Week 2 keeps the first half. Week 3 keeps the first three quarters. Week 4 keeps the whole file. Rates, the weekly chart, the invalid-type bars, the ranker, and the what-if all use that slice. The week-1 sentence says those are the dates that would have arrived first, so the story does not peek ahead. When every date in the file is already inside the slice, the sentence says this week uses the whole file.

Week 1 also shows the opening note that the old loop stored as week 0, plus the week-1 note. There is no week 0 on the page.

The break menu defaults to the ranker's column (`_default_break`, `src/invalid_agent/ui/story.py:470`). Blank levels (`UNREPORTED`) are left out of the table. The caption says a blank is not a cause.

A what-if that clears every invalid says `0%` and explains that this is a pretend cleanup, not a new test (`_projection_sentence`, `src/invalid_agent/ui/story.py:400`). It does not print `0.00%`.

Plan tickets come from `build_plan`. Display keys are `INV-1`, `INV-2`, and so on, in plan order, including the tasks from the old week 0 inside week 1. The old "Retest" task name is "Check the next-best group again". A confirmed typed insight is not given the next INV number. It is "Your ticket 1", then "Your ticket 2". The reply says a real team would put that in Jira. This page does not create that ticket. Show me does not use those numbers.

The week's call is "Look harder" or "Watch". It is not "Hold". Week 4 may still recommend holding one group, because that sentence is the recommendation, not the call label.

The decision for week 2 or 3 compares this week's leading group with the previous week's slice. It does not reuse a fixed sentence.

The complaint does not print a separate MAUDE, OOI, and JJE glossary, and the device line does not repeat those meanings. The public banner already explains MAUDE, so the case title keeps the short form. OOI is explained once. `gloss_once` (`src/invalid_agent/ui/plain.py:190`) matches a code name without caring about capital letters, so "No usable result (INV-NOR)" is not written twice. The talk-back glossary still answers "What is MAUDE?" if the reader asks.

The wrap-up text is built for the week on screen. Week 4 does not hide the recommendation behind a button.

## Talk-back

`respond` (`src/invalid_agent/ui/talkback.py:176`) classifies the message against facts already on screen. The part order is complaint, numbers, charts, logged, notes, wrap-up. A claim that names invalid types as "most" or "biggest" before the charts part is `early`: the reply is `NOT YET — you'll see that on the charts part.` There is no ticket and no flag. A "going up", "increasing", "going down", or "decreasing" statement before the numbers part is the same kind of early reply, naming the numbers part.

A question, including one that starts with "would" or hides the question mark in parentheses, is answered and is not a ticket. "What is the invalid rate this week?" returns the rate sentence, not the chart sentence. A statement that denies a count, such as "INV-NOR is not the biggest", is a direct correction when the counts disagree and a short agreement when they agree. It is not labeled "GOOD QUESTION." and it does not get a ticket. Doubt is a phrase, not the bare word "wrong": "I doubt", "I don't believe", "no way", "unlikely", "it's false", "false that", and "isn't even close" are not confirmed and do not get a ticket. The gap between "not" and "biggest" can include a hyphenated code, so "It's not true that INV-IC is the biggest" is a denial. "I doubt that" on the complaint stays on the complaint. It does not answer with the charts. "The rate is not going down" is not a flag when the rate is not falling. A code named right after "not", as in "the top two, not INV-SW", is left out of the claim. A code name that contains "not" or "wrong", such as "not enough sample" or "used it the wrong way", can still be confirmed when the counts agree. "hello", "asdf", and a remark that is not a question are a tip, not "GOOD QUESTION."

A correct insight returns a bullet and logs "Your ticket N". `_key_statement` (`src/invalid_agent/ui/talkback.py:575`) confirms a typed statement only when it states the fact on screen. Pasting the sentence on the screen confirms it. Putting "not" in front of that sentence does not. The promise has to say 98% valid, or at most 2% invalid, and "valid" inside "invalid" does not count. "I don't believe", "we doubt", and "not true" do not confirm the claim that follows, including when a code name sits in parentheses. The logged part uses `_shown_ticket_count` (`src/invalid_agent/ui/talkback.py:479`), the rows on this week's table, and the typed number has to be that count. A public-report case can say "share of reports" instead of "rate". A note or a wrap-up confirms only when the typed words restate one sentence on screen, so "I recommend pizza" does not. A week with no invalids does not invent a majority. `_apply_talk` (`app/streamlit_app.py:240`) appends an open item. The same finding sent again does not take a new number. A partly right or unsupported insight logs a flag (`Flag 1`, `Flag 2`, ...) and that flag is in the Week N insights list, labeled Flag. Two unsupported claims about different codes do not share one flag signature. A question, including "What is MAUDE?" and "Who made the device?", gets a plain answer and logs nothing. Typed tickets and flags from earlier weeks are shown at the top of the next week, with the key printed once. Show me insights are not.

`example_prompts` (`src/invalid_agent/ui/talkback.py:147`) builds three clickable prompts from the same view. The button label goes through `gloss_once`, so a code already explained on the page stays short. The click still sends the original prompt. The "make up most of the invalids" prompt is not offered before the charts part. "Why is the invalid rate going up?" is on every part.

`reword_reply` (`src/invalid_agent/ui/talkback.py:207`) calls the model only when fixed wording is off and a model exists. `_draft_ok` (`src/invalid_agent/ui/talkback.py:230`) keeps the draft only when it still starts with the same opening verdict, the number tokens are the same sequence as the plain reply, the draft is negated only when the plain reply is negated, a ticket or flag id is still there as its own id, `unexplained_jargon` is empty, and `check_narrative` accepts the draft. A NOT QUITE or CLOSE draft that adds praise ("great job", "you nailed it", "perfect") is rejected. Swapping 4.00% and 1.00% is rejected. Putting "NOT" into a YEP reply is rejected. The facts passed to `check_narrative` are the numbers parsed from the plain reply plus the ticket and flag ids. The plain reply itself is not passed as a string, because a long fact string would hide extra numbers. A draft that adds a number, lengthens the verdict, or uses an unexplained term is rejected. Any failure returns the plain reply. The page never prints "Fidelity ok" or "model draft was rejected".

## Words

`src/invalid_agent/ui/plain.py` holds the banners, the percent formatter, and `unexplained_jargon`. The check is per sentence. A gloss in one sentence does not excuse the same word in the next sentence. The page lint runs that check on each rendered element, not on the page glued together. A term such as MAUDE, OOI, JJE, openFDA, fishbone, containment, or Wilson may appear only when the same sentence explains it. The page does not use the bare words estimable, Pareto, strata, fidelity, pooled, control chart, Western Electric, lift, UCL, LCL, p-chart, denominator, deterministic, or narrative. Case-file sentences that already contain one of those words go through `with_gloss` before they are shown. On the page, `gloss_once` explains MAUDE, OOI, JJE, and each INV code the first time that token appears, and later sentences keep the short form. A sentence that is only "What is MAUDE?" is allowed, and "(FDA product code OOI)" is allowed, because the question or the label is the term itself. A bare OOI in a normal sentence is still unexplained. "nucleic acid" counts as the OOI gloss, as does "nucleic-acid". Agent write-ups go through `soften` and then `safe_prose`, which drops a sentence that still fails.

A public-report deck says "the company that made the device" instead of `reported_manufacturer` on the call line, and its impact slide does not print a dollar amount per invalid. A practice deck still prints the practice cost line.
